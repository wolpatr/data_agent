The Agent Loop

Your mission is an agent that buys and sells crypto unsupervised.mission Good news: every autonomous trading bot ever built — from hobby scripts to the systems analyzed in research surveys[1] — is a variation of the same four-step cycle. Learn this loop and you hold the skeleton of the whole project. Everything else (better signals, lower fees, smarter classifiers) lives inside one of these four boxes.

1 · Observe — read the market

Pull current market state: a ticker (last price), historical candles (OHLCV), or the full order book. You will not hand-roll this: the CCXT library gives one unified API (JavaScript, Python, and more) for 100+ exchanges (verified, `npm install ccxt` / `pip install ccxt`), so your Observe code survives switching exchanges later.

2 · Decide — classify the situation

A decision function takes (market state, current position) and returns BUY | SELL | HOLD plus a reason. The "analyser that triggers when to buy and sell" you described lives entirely here. The field already has decades of this: technical-indicator rules,[1] classical ML classifiers — 41 of them benchmarked on Bitcoin with trading metrics[2] — and even LLM-based agents.[3] Your job per mission is to borrow from that line of work, not invent strategy #147.

3 · Execute — place the order

Translate the decision into an actual order and submit it to the exchange. This is where the real world fights back: minimum order sizes, insufficient balance, timeouts, partial fills. Battle-tested bots treat execution error handling as a first-class subsystem, not an afterthought.[4]

4 · Evaluate — close the loop

Log what happened, compare it to what you expected, and let that record improve future decisions. The CryptoTrade paper formalises this as a reflective mechanism — the agent reviews past decisions to refine the next ones.[3] Autonomy without evaluation is just a blind slot machine.

Why the ladder matters: backtest → paper → live

Autonomy means nobody double-checks in the moment, so safety comes from the loop itself: test on historical data (backtesting), then run with fake money (dry-run / paper trading), then — only then — real money. Freqtrade, the most battle-tested open-source crypto bot, is emphatic: "Always start by running a trading bot in Dry-run."[4]

Run one yourself

The simulator below is the four boxes live. The Decide step uses a classic signal: an EMA crossover — when the fast average crosses above the slow average, the market may be turning up (BUY); the reverse is a SELL.

Tight-feedback exercise (2 min): press Autoplay and watch equity. Reset, then try fast=20, slow=30; reset, then fast=3, slow=50. Notice: no parameter pair wins in every regime — sideways markets chop the crossover strategy to pieces. Keep that observation; it is the exact reason Lesson 0002 is about transaction costs and honest testing.

Check yourself (instant feedback)

The agent just decided SELL. Which module turns that into an order on the exchange?

Decide only outputs an intention (BUY/SELL/HOLD). Execute is the box that turns it into a real order via the exchange API.

Why does the mission climb backtest → paper → live instead of going straight to live?

With no human in the loop, the ladder of closed feedback loops is the safety system. Exchanges do not require it; the mission's risk discipline does.
